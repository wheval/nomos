## Authentication

Every endpoint below authenticates with your **secret key** as a bearer token.
Find it in the console under **Developers → API keys**.

```bash
curl https://your-nomos-host/api/payments?to=0xYOURADDRESS&network=0 \
  -H "Authorization: Bearer $NOMOS_SECRET_KEY"
```

Test and live keys are separate credentials, exactly as with Paystack or
Stripe: a test key can never authenticate a live-mode request. `networkIndex`
is `0` for mainnet and `2` for Sepolia, and it always has to match the key.

Never put a secret key in front-end code. The **public key** is the one that is
safe to embed.

## Checkout Sessions

Create one per order when a customer is ready to pay. See
[Checkout](/docs/checkout) for how this differs from a Payment Link.

### Create a session

`POST /api/checkout/sessions`

```bash
curl -X POST https://your-nomos-host/api/checkout/sessions \
  -H "Authorization: Bearer $NOMOS_SECRET_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "merchantAddress": "0x...",
    "networkIndex": 0,
    "token": "USDC",
    "amount": "25",
    "reference": "order_9182",
    "description": "One t-shirt",
    "callbackUrl": "https://shop.example/thanks"
  }'
```

Returns `201` with a `url` to redirect the customer to. `amount` is required,
`reference` is your own order id, and `expiresIn` defaults to 1800 seconds.

### Read a session

`GET /api/checkout/sessions/{id}`

Returns `status` — `open`, `processing`, `paid`, `expired`, `revoked` or
`failed` — and, once settled, a `payment` object with the transaction hash and
what was credited after fees.

## Payment Links

### Create a link

`POST /api/payment-links`

```bash
curl -X POST https://your-nomos-host/api/payment-links \
  -H "Authorization: Bearer $NOMOS_SECRET_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "merchantAddress": "0x...",
    "networkIndex": 0,
    "token": "USDC",
    "amount": "25",
    "note": "Consulting, October",
    "singleUse": false
  }'
```

Omit `amount` for a link the payer fills in themselves. Set `singleUse: true`
for an invoice — it closes after the first payment and tells anyone who opens
it later that it is already paid. `expiresIn` takes seconds.

The response carries the link `id`; the payable URL is `/pay?id={id}`.

### List and revoke

`GET /api/payment-links?to={address}&network={n}` lists your links.
`DELETE /api/payment-links/{id}` revokes one so it stops accepting payments.

## Verify a payment

`GET /api/transactions/{reference}`

The single call to make from a webhook handler or an order page. `reference` is
the per-payment id — distinct from your own order reference — returned when a
payment settles.

```bash
curl https://your-nomos-host/api/transactions/nx_7f21c9... \
  -H "Authorization: Bearer $NOMOS_SECRET_KEY"
```

Returns `status: success | pending | failed`. Treat anything other than
`success` as unpaid, and never ship an order on a redirect alone — a customer
can close the tab before it happens.

## Balances and payments

`GET /api/payments?to={address}&network={n}`

Returns your recorded payments and your current balance per token. Amounts are
strings in each token's smallest unit, because they exceed what a JSON number
holds safely.

Each payment carries `amountWei` (what the customer paid) and `feeWei` (the
Nomos fee); the difference is what was credited. See [Pricing](/docs/pricing).

## Payouts

`POST /api/payouts`

```bash
curl -X POST https://your-nomos-host/api/payouts \
  -H "Authorization: Bearer $NOMOS_SECRET_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "merchantAddress": "0x...",
    "networkIndex": 0,
    "token": "USDC",
    "amountWei": "25000000",
    "destination": "0x...",
    "mode": "withdraw"
  }'
```

`mode` is `withdraw` to settle publicly at the destination, or `transfer` to
keep it shielded — the destination then needs its own STRK20-capable wallet.

The response reports `sentWei` and `feeWei` separately: the payout fee comes
out of the amount requested, so the destination receives slightly less than you
asked for. Payouts have a minimum, and cost the same to settle whether they
cover one payment or fifty — so withdraw in batches.

`GET /api/payouts?to={address}&network={n}` returns payout history.

## Errors

Every failure returns a JSON body with an `error` string and a meaningful
status: `400` for a malformed request, `401` for a bad or missing key, `404`
for something that does not exist, `409` for a conflict such as an invoice
already paid, `410` for a link that is revoked or expired, and `422` when a
request is well-formed but cannot be satisfied — an amount below the minimum, a
payout larger than the balance, a payment that fails on-chain verification.
